## Sources and evidence boundaries

- `figures.mjs` is the authored specification: placement, wording, source links, evidence label and interpretation boundary.
- `uploaded-figures.mjs`, `uploaded-taxonomy-continuation.mjs`, `uploaded-incidents.mjs`, `uploaded-detection-sources.mjs` and `uploaded-credentials.mjs` contain reviewed mappings, captions, caveats and text equivalents. `uploads-provenance.json` records original names, dimensions, byte counts, image hashes, five ZIP hashes and eleven supporting-document hashes. Importing does not redraw or compress artwork; no claim is made about its creation process. The register snapshot fails validation if its baked-in counts or review date no longer match `research/anomaly-incidents.json`.
- `scripts/lib/anomaly-visuals.mjs` renders the remaining editable, self-contained SVGs without an image model, remote font, tracking code, embedded script or external raster.
- Family diagrams are author-proposed operational schematics. NIST supports the anomaly-detection foundation, not an official standardized 14-family taxonomy or these exact candidate methods. Their adjacent incident cards retain the source-reported examples and limitations.
- The 12 uploaded campaign diagrams distinguish a source-reported observation from the author's detection hypothesis. They are not victim-telemetry reconstructions. Their S01–S14 codes resolve through nearby primary-source links and the unchanged supplied `uploaded-incident-sources.md`. Captions qualify RDAT channel coexistence, IFM terminology and the separate Storm/APT41 reports. Official CISA/CSRB documents could not be retrieved for fresh full-text review; those accounts remain explicitly source-attributed. Incident durations and detector success rates have not been invented.
- The nine detection-source uploads distinguish documented capabilities from verified local collection. Their complete package, including supplied text and source notes, is retained under `static/research/anomaly-visuals/uploaded-detection/`. The importer checks its supplied image manifest against real bytes. Captions clarify the EDR event key, source-specific visibility, unmeasured planning advice and the unresolved AWS documentation discrepancy. No endpoint, IAM, EDR or cloud collection was exercised by importing these diagrams.
- The four credential-attack uploads replace the matching Section 6 figures. Their nine-file package is preserved under `static/research/anomaly-visuals/uploaded-credentials/`. Primary sources support the displayed event meanings, rights GUIDs and access bits. The two LSASS mask decompositions are independently recalculated, without trusting the supplied validation flag. ## Regeneration

```bash
npm run research:revision:render
npm run research:anomalies:check
npm run research:uploads:verify
```

For the first batch, run `node scripts/import_anomaly_uploads.mjs --taxonomy-dir <safely-extracted-first-zip-directory> --definitions-dir <original-png-directory> --archive <first-zip-path>`. For Sections 2.11–2.16, run `node scripts/import_anomaly_uploads.mjs --continuation-dir <safely-extracted-second-zip-directory> --continuation-archive <second-zip-path>`. For Sections 4.1–4.12, run `node scripts/import_anomaly_uploads.mjs --incidents-dir <safely-extracted-third-zip-directory> --incidents-archive <third-zip-path>`. The importer validates PNG/JPEG headers, preserves earlier provenance and refuses to overwrite an existing asset with different bytes. It also preserves the third ZIP's source notes as data, not executable instructions. Original-resolution uploads do not acquire a reflowed narrow layout: use the full-resolution link or HTML text equivalent on small screens.

For Sections 5.1–5.9, run `node scripts/import_anomaly_uploads.mjs --detection-dir <safely-extracted-fourth-zip-directory> --detection-archive <fourth-zip-path>`. All fourteen package members are preserved in their original relative layout under `uploaded-detection/`. The public manifest binds the reviewed captions and supporting files. The build verifier checks nested assets as well as top-level images.

For Sections 6.1–6.4, run `node scripts/import_anomaly_uploads.mjs --credentials-dir <safely-extracted-fifth-zip-directory> --credentials-archive <fifth-zip-path>`. All nine members retain their relative layout under `uploaded-credentials/`; each image must match the supplied manifest before import. The source tests preserve the section prose and verify all supporting hashes and mask arithmetic.

The browser checker needs Playwright and Chromium/Google Chrome. Its defaults match this workstation; override `--playwright` when using another installation. Full article checks use read-only shell assets from the adjacent `anomaly-revision-release` checkout or `--site-root`. Builds need the archive's locked Node dependencies. Scripts write only generated assets, local build output and verification reports; they do not publish.

The upload verification command stores output under `reports/anomaly-uploaded-credentials-61-64-20260921/`; all earlier report directories, including `anomaly-uploaded-detection-51-59-20260921`, remain historical snapshots and must not be overwritten. Browser checks cover text geometry in 20 active SVGs, native decoding of all 45 raster images in both variant slots, and all 55 figures in six viewport/theme combinations. They also check aspect ratios, preserved anchors, page overflow and JavaScript errors. Contact sheets and screenshots support manual review. Raster decoding does not test text correctness inside a bitmap; the artwork was separately inspected and qualified in captions. These checks establish rendering and consistency, not independent factual certification.

The checker also uses `axe-core` from the website checkout to reject color-only text links and non-focusable scroll regions. Markdown tables use the shared MDX table component with keyboard focus and a visible outline; figure-caption links are underlined. These are regression checks added after the first release CI exposed accessibility gaps.

All 55 text-equivalent panels are expanded during these checks. Raw data blocks are also keyboard-focusable, including the wide synthetic-results JSON on narrow screens.

## Editing discipline

Edit the authored figure specification, not generated SVG or manifest files. Keep figure numbers in reading order. The register graphic is reinserted inside the managed index block by `insertFigures`; do not insert it manually into generator output. Run the evidence checks after changing the research data. Preserve existing URLs, anchors, incident cards, queries and historical media. Do not silently replace missing measurements with schematic numbers. A new fact or incident requires a supporting primary source and review of both the text and diagram.

Each inline figure includes a source-linked caption, text equivalent and a full-size link. `<picture>` chooses a narrow variant for generated SVGs; uploaded rasters retain the original image at every viewport width. The old-media accordion contains only historical images; no current diagram is hidden inside it. The article cover and calculated research-result diagrams are unchanged.
